# Projektsteuerung, Roadmaps und Übergaben

**Quellen:** Export-Chats „Toolya Audit erstellen“, „Toolya Audit Fortschritt“, „Toolya Roadmap prüfen“, „Projekt bereinigen“, „Toolya Releaseabnahme“, „Toolya-Roadmap weiter umsetzen“; AGENTS.md, docs/audits/toolya-roadmap.md.

## Arbeitsregeln
- Möglichst autonom in großen, zusammenhängenden Schritten; tatsächliche Ergebnisse und Tests nachweisen statt wiederholter „Weiter“-Schleifen.
- Entscheidungen, offene Punkte und Abnahmen versioniert dokumentieren.
- GitHub main und tatsächlicher Live-Stand sind für Implementierungsbehauptungen maßgeblich; ein Chatbericht ist nur historischer Hinweis.
- Produktive Supabase-Daten, Secrets und reale Nutzerdaten schützen; keine unnötigen Tests in Produktion.
- Vor Veröffentlichung PR/CI/Pages/Live kontrollieren, aber diese Wissensarbeit führt **keinen** Merge oder Deployment aus.

## Offene Prozessarbeit
Aktuellen Branch-/PR- und CI-Stand inventarisieren; veraltete Roadmap-Stati nur mit konkretem Nachweis korrigieren. Alle zukünftigen Chat-Übergaben auf diese Wissensbasis und konkrete Quellverweise beziehen.
